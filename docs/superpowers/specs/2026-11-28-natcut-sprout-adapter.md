# NatCut plant-job adapter boundary

Status: offline adapter slice; no live route or deployment.

NatCut calls the private Sprout Cloud Run origin with an injectable OIDC ID-token provider whose audience is that exact origin. The v1 client sends JSON with raw `sanitizedImageBase64`, the source-photo SHA-256 and receipt, and `Idempotency-Key: generationIntentId`. It parses allowlisted create, status and outcome responses. Candidate bytes come from the authenticated same-service candidate endpoint and must match the status media type, declared length and SHA-256 before trusted sprite normalization.

`natcutPlantFlows` is NatCut-owned state. A Firestore transaction binds one event, visitor session and capture to an immutable intent ID, request fingerprint, fallback asset and absolute deadline. The sanitized photo bytes and provider details are not stored in this record. A lost create response can be retried with the original intent and deadline; a changed photo or policy with the same capture conflicts. A second transaction binds the Sprout job ID once. A final transaction commits the first local outcome. The visitor receives that local outcome immediately with a pending Sprout acknowledgement. A separate `syncOutcome` call sends the exact decision and records confirmed or reconciliation state; a lost response can be retried. The local outcome remains fixed when Sprout acknowledges late or ambiguously.

The local deadline starts with the confirmed photo intent and is capped by both the persisted UTC deadline and a process-local monotonic clock. Retrying a create or polling from another process cannot extend the persisted deadline. Status reads are bounded by the remaining wait. At 15 seconds without an accepted generated asset, NatCut commits the selected approved catalog fallback only after Sprout has confirmed generation eligibility. A candidate produced later never changes that decision. Below-threshold identification keeps its suggestions for retake or manual selection; it never auto-accepts fallback. Unknown or contradictory eligibility enters reconciliation. The operator may explicitly accept the catalog fallback from a valid review state. The coordinator does not create a print submission or reserve a printer slot.

The generated-candidate path depends on `TrustedCandidateRegistrar`. Its adapter runs the merged `normalizeSpritePng` boundary after verifying fetched bytes. The injected writer's `stage` operation must durably store the normalized PNG, colour evidence, source digest, candidate ID and Sprout object generation in a private, unlisted location. Staging must not make an asset visible or loadable by a visitor or print submission. A stage operation may finish after fallback commits; that orphan remains private for cleanup. Only after the local `generated_accepted` decision wins may a future trusted loader resolve the staged ID, and it must verify the accepted decision and exact immutable storage generation. This writer and loader are deliberately not implemented in this slice: the merged `catalog-v1` loader reads only packaged sprite IDs, so normalization alone cannot make a generated candidate printable. A later reviewed runtime catalog contract must establish immutable storage generation, descriptor identity, conditional promotion, retention through physical completion, and trusted loader lookup before the generated acceptance path is wired to a live route.

The source-photo receipt is distinct from NatCut's logical print artifact. It proves only the sanitized input supplied to Sprout. The existing portrait contracts are independent. No provider credential or private Sprout object path enters the visitor response.

## Remaining integration gates

- Wire an authenticated NatCut visitor endpoint after the phone capture lane supplies a stable sanitized photo receipt and ownership check.
- Implement and review the durable runtime sprite catalog writer and trusted loader before enabling generated acceptance in production.
- Wire the OIDC token provider, private service URL, Firestore repository and Sprout service contract after both lanes pass review.
- Set rollout controls and retention/privacy policy before deployment. No paid provider call or printer action is part of this adapter slice.
