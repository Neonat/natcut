# LAN Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an explicit `npm run dev:lan` command that lets a phone on the same Wi-Fi open NatCut by scanning a terminal QR code while operator controls remain Mac-only.

**Architecture:** Extract LAN address selection and runtime configuration into testable helpers. The existing process orchestrator consumes either loopback or LAN configuration; LAN mode uses a dedicated Firebase emulator config to expose Auth but not Firestore, and prints a QR code after every required service is reachable.

**Tech Stack:** Node.js 24, Firebase Local Emulator Suite, Vite, Fastify/CORS, `qrcode-terminal`, `node:test`

**Spec:** `docs/superpowers/specs/2026-11-24-lan-demo-design.md`

## Global Constraints

- `npm run dev` must remain loopback-only.
- LAN mode must use only Firebase project `demo-natcut`.
- Ports are fixed: visitor `4174`, submission API `8088`, Auth emulator `9099`, Firestore emulator `8080`, control server `8090`.
- Control port `8090` and Firestore port `8080` remain bound to `127.0.0.1`.
- No printer protocol or mutation command may be added.
- Node.js `24.12.0` or newer remains required.

## Review Focus

- A machine with only loopback/link-local addresses must fail before launching children.
- Multiple interfaces must deterministically prefer an active private IPv4 address.
- LAN mode must not expose the control server or Firestore emulator.
- The phone-facing API and Auth URLs must use the same selected address as the QR code.
- A changed Wi-Fi address must require restart rather than leaving stale runtime configuration.
